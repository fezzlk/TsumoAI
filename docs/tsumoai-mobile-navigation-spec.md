# TsumoAI モバイルナビゲーション仕様

## 1. 目的

TsumoAIを開いた利用者が、目的に合う機能へ迷わず入り、縦持ちのまま結果確認まで完了できる画面遷移を定義する。本書をナビゲーション図の内容上の正本とし、draw.ioは本書を視覚化する。

## 2. 共通原則

- 一般ホームで利用目的を最初に選ぶ。
- 点数計算、待ち確認、AI相談、対局開始はログインなしで利用できる。
- ログインは任意とする。ログイン中は履歴をアカウントへ紐付けて自動同期し、学習データ送信時は未ログインの場合だけ求める。
- 一般ホームには、未ログイン時はログインボタン、ログイン中はメールアドレスとログアウトボタンを表示する。
- 撮影、訂正、条件入力、結果確認、対局管理は縦画面だけで完了する。
- 単発確認では、ホームで選んだ目的を結果画面で選び直させない。
- 一般ホームから始める単発確認は局状態を持たない。対局ホーム内の「すぐ確認」から始める単発確認は、現在の場・局・親・本場・登録済みの表ドラを読み取り専用の初期値として引き継ぐ。手牌、対象席、立直、裏ドラ、認識訂正は確認ごとに扱う。確認の完了だけでは局状態を更新せず、同じ対局ホームへ戻る。
- 枠、牌、検出枚数、和了牌の確認と訂正は結果画面で行う。
- 一般利用者画面には牌分類モデルのversionやsourceを表示しない。

## 3. ユースケース

### UC-01 すぐ確認する

**目的:** 局管理を始めず、現在の手牌について点数、待ち、打牌または鳴き判断を確認する。

**開始:** 一般ホーム。

**基本フロー:** 

1. 「点数計算」「待ち確認」「AI相談」のいずれかを選ぶ。
2. AI相談の場合は「何を切る」「鳴くべきか」を選ぶ。
3. 縦持ちカメラを開く。牌数の初期値は、点数計算・「何を切る」では14枚、待ち確認・鳴き判断では13枚とする。カメラ画面に常時表示する「自動・13・14・15・16・17・18」から1タップで変更できるようにする。専用画面、ドロップダウン、「その他」の展開操作は設けない。横幅が足りない端末では選択肢の列だけを横スクロール可能にする。
4. 枠が安定したら自動確定し、位置検出と牌識別を行う。手動撮影も利用できる。
5. 結果画面で枠、牌、枚数、和了牌を確認・訂正する。推定枚数が違う場合は「自動」または13〜18枚を選び直し、同じ画像から位置検出と牌識別を再実行する。
6. 手動トリミングを使った場合は、指定範囲から端末内で再検出する。
7. ホームで選んだ目的の結果を表示する。

**目的別の終点:** 

- 点数計算: ツモの場合とロンの場合の役、翻、符、支払いを両方表示する。
- 待ち確認: 待ち牌、残り枚数、点数見込みを表示する。
- AI相談: 決定的ロジックの結果を根拠にAIが説明し、必要なら卓況をチャットで追加する。

**鳴き判断:** 実際に牌が捨てられた後の操作支援ではなく、現在の手牌から今後鳴ける可能性のある牌とチー・ポン・カンを事前に一覧表示し、鳴く前後のシャンテン、受け入れ、役候補などを比較する。相手の捨て牌や捨てた相手は入力させない。リーチが入っている、点数状況に余裕がある等の卓況は任意入力とし、計算済み候補を根拠に同じ結果画面からAIへチャット質問できるようにする。

**結果後:** 「別の確認」では確定した画像、枠、牌を再利用する。完了時は一般ホームへ戻る。

### UC-02 対局セッションで和了を処理する

**目的:** 1台の端末を卓内で共有し、現在局を保持しながら和了結果を確認する。

**開始:** 一般ホームの「対局を始める」、または継続中の対局ホーム。

専用の対局開始画面や席合わせ画面は設けない。「対局を始める」から東1局0本場の対局ホームへ直接進む。

**基本フロー:** 

1. 対局ホームに現在の場、局、本場、親を表示する。
2. 同じ画面内に「和了者選択」の見出しと起家基準の4席を座席図ボタンとして表示し、和了者の物理席をワンタップで選ぶ。「和了」ボタンと座席図を別々に置かない。
3. 縦持ちカメラで自動スキャンする。
4. 端末内で位置検出、crop、牌識別を行う。
5. 手順4と並行して、立直、表ドラ、立直時の裏ドラを順に入力する。
6. 認識と必須条件の両方がそろったら結果画面へ進む。
7. ツモの場合とロンの場合を両方表示し、枠、牌、枚数、和了牌、ドラ、条件を訂正できるようにする。
8. 「この結果で局終了」を押した時だけ局、親、本場を更新し、対局ホームへ戻る。

ツモ／ロンは条件として入力させず、専用の確認画面も設けない。同じ確定手牌と共通条件から両方を計算して結果画面へ並べる。

**局進行:** 東、南、西、北を扱う。南4局の次は西1局へ進み、その後も対局ホームの「対局終了」が押されるまで進行する。

### UC-03 対局ホームで補助操作を行う

**開始:** 対局ホーム。

**操作と終点:** 

- 流局: 親継続または親交代を選び、局状態を更新して対局ホームへ戻る。
- すぐ確認: 点数、待ち、AI相談を単発で利用する。現在の場・局・親・本場・登録済みの表ドラを引き継いで計算・説明に利用するが、確認の完了では局を進めず対局ホームへ戻る。
- 1局戻す: 直前の局状態を復元し、対局ホームへ戻る。
- 対局終了: 未確定の入力がある場合だけ破棄を確認し、対局を終了する。

### UC-04 履歴を見る・アカウント同期する

**目的:** 過去の結果を参照する。ログイン中は履歴をアカウントへ紐付け、同じアカウントの履歴を自動同期する。

**基本フロー:** 

1. 一般ホームから利用履歴を開く。
2. 端末内履歴はログインなしで表示する。
3. ログイン中は新しい履歴をアカウントへ自動的に紐付ける。
4. 同じアカウントに紐付いた履歴を自動的に取得して一覧へ表示する。

利用者にバックアップ・復元の操作はさせない。リアルタイム共同対局、進行中セッションの共有、元画像の既定同期は行わない。

### UC-05 学習データ作成へ協力する

**開始:** 設定。

**基本フロー:** 

1. 「学習データ作成ボタンを表示」をONにする。
2. ホームと認識結果へ学習データ作成・送信導線を表示する。
3. 認識結果を正しい牌へ訂正する。
4. 送信時に未ログインならGoogleログインを求める。
5. 訂正後の正解と、認識時の予測、confidence、model version/source、前処理versionを送る。

### UC-06 運用管理する

**開始:** 設定。

**基本フロー:** 

1. Firebase ID tokenのadmin claimを確認する。
2. adminでなければ一般利用者として設定へ戻る。
3. adminの場合だけ開発者メニューを表示する。
4. 学習データ管理、再学習、モデル承認、ロールバックへ進める。

認証失敗またはネットワーク失敗時は一般利用者として扱う。

## 4. draw.ioページ構成

| ページ | 表現する内容 | 描かない内容 |
|---|---|---|
| `01_利用目的から見る全体導線` | 一般ホームから4種類の目的へ分かれる全体像 | 個別画面の訂正ループ |
| `02_すぐ確認の共通撮影と目的別結果` | UC-01の共通撮影と3種類の結果。一般ホーム起点は局状態なし | 対局ホーム起点で引き継ぐ局状態の詳細 |
| `03_対局セッション_和了した1局` | UC-02の通常成功フローと並行処理 | 流局、1局戻す、終了 |
| `04_対局ホームの補助操作` | UC-03の4操作と各終点 | 和了処理の詳細 |
| `05_履歴ログイン設定と管理導線` | UC-04〜06のログイン境界と権限境界 | Web管理画面内部 |

## 5. 図への変換ルール

- 1ページでは一つの主要質問だけに答える。
- 基本フローは左から右、または上から下の一方向にそろえる。
- 戻り先は終点の文言で示し、長い戻り矢印を増やさない。
- 並行処理、利用者判断、権限分岐だけを明示的な分岐として描く。
- 矢印は関係のない枠、タイトル、説明文を横切らない。
- 同じ意味の画面や処理をページ内で重複させない。
