# TsumoAI 画面レイアウト図仕様

- 更新日: 2026-09-21
- 対象: モバイル縦画面、Web管理画面
- 状態: 合意済み要件に基づく目標レイアウト。実装済みを示す資料ではない
- 編集可能な図: [TsumoAI 画面レイアウト（draw.io）](./tsumoai-screen-layout.drawio)

## 1. 目的と読者

本書は、実装者とレビュー担当者が「各画面で何がどこに表示され、どの操作を何タップで行うか」を確認するための、画面レイアウト図の意味上の正本である。画面間の遷移は [モバイルナビゲーション仕様](./tsumoai-mobile-navigation-spec.md) と [モバイルナビゲーション図](./tsumoai-mobile-navigation.drawio) を参照する。

図は情報階層と操作位置を定義する。色、フォント、最終的な余白は実装と実機確認で調整する。

## 2. 共通ルール

- 一般利用者向けモバイル画面は縦持ちで完結する。
- 主要操作は片手で押しやすい画面中央から下部へ置き、48dp以上のタップ領域を確保する。
- 1タップで選べる項目をドロップダウンへ隠さない。選択直後に次へ進める設問には確定ボタンを置かない。
- 撮影、認識、条件入力、訂正の途中には広告を置かない。
- 枚数指定は「自動・13・14・15・16・17・18」を常時見せる。初期選択は点数計算・「何を切る」で14枚、待ち確認・鳴き判断で13枚とする。横幅不足時はチップ列だけを横スクロールし、展開操作は加えない。
- 検出枠、牌、枚数、和了牌の訂正は結果画面へ集約する。
- 一般画面にモデルversion、source、前処理versionを表示しない。
- 図中の画面はすべて目標設計であり、現行実装との差分はLinearで管理する。

## 3. 画面別レイアウト

### 3.1 一般ホーム

**答える質問:** 利用者は目的を迷わず選び、アカウント状態も確認できるか。

- 上部: サービス名、短い説明、ログイン状態。ログイン中はメールアドレスとログアウト、未ログインはログイン。
- 主領域: 「すぐ確認」の点数計算、待ち確認、AI相談を大きなカードで表示する。
- 次領域: 対局開始を横幅いっぱいの主要ボタン、履歴を補助ボタンとして表示する。
- 下部: 使い方、設定・規約。設定ON時だけ「学習用の牌を1枚撮影」を表示する。
- 無料利用時の広告は最下部に限定する。

### 3.2 共通カメラ

**答える質問:** 縦持ちのまま、枚数を必要なら1タップで指定し、自動スキャンの状態を理解できるか。

- 上部: 戻る、現在の検出枚数、スキャン状態。
- 直下: 「自動・13・14・15・16・17・18」の直接選択チップ。点数計算・「何を切る」では14、待ち確認・鳴き判断では13を初期選択する。
- 中央: カメラプレビュー。横長の撮影ガイド、検出枠、安定度を重ねる。
- 下部: 自動確定までの案内。手動撮影は自動確定できない場合の復旧操作として置く。
- 枚数変更時は同じカメラ入力で検出を継続し、別画面へ遷移しない。

### 3.3 認識確認・目的別結果

**答える質問:** 認識の誤りを直しながら、選択済み目的の結果を確認できるか。

- 上部: 選択済み目的と検出枚数。枚数チップを直接表示し、変更時は同じ画像から再検出する。
- 画像領域: 元画像と検出枠。「範囲を切り抜く」で実装済みの手動トリミングへ進む。
- 牌領域: 読める大きさを保つ横スクロール列。牌タップで種類訂正、枠追加・削除、撮り直しを行う。
- 結果領域: 点数ではツモ・ロンの両方、待ちでは待ち牌、AI相談では決定的計算を根拠とする説明を表示する。
- 下部: 条件訂正、別目的で同じ認識結果を使う操作。設定ON時だけ訂正データ送信を表示する。

### 3.4 対局ホーム

**答える質問:** 現在局を確認し、和了者の物理席を1タップで選べるか。

- 上部: 東南西北、局、本場、親をまとめた局情報カード。
- 中央: 「和了者を選択」の直下に、起家を明示した4席の座席図ボタンを置く。別の和了ボタンは置かない。
- 補助操作: 流局、1局戻す、対局終了。
- 下部: 現在の場・局・親・本場・登録済みの表ドラを引き継ぐ「すぐ確認」の点数、待ち、AI相談。確認の完了だけでは局を進めない。

### 3.5 認識中の条件入力

**答える質問:** 認識待ち時間を使い、最低限の条件を少ない操作で入力できるか。

- 上部に認識進捗を常時表示する。
- 立直は「はい／いいえ」を1タップで選び、直ちに次へ進む。
- 表ドラ表示牌は牌一覧から選び、0枚のまま次へ進める。結果画面でも追加・修正できる。
- 立直ありの場合だけ裏ドラ表示牌を続けて選ぶ。
- ツモ／ロンは入力させず、結果画面に両方を表示する。
- 認識が先に終わっても入力中の画面を奪わず、条件入力完了後に結果へ進む。

### 3.6 履歴・設定・学習協力

**答える質問:** 任意ログイン、履歴同期、学習協力の設定を誤解なく扱えるか。

- 履歴: 種類フィルター、結果一覧、ログイン時の同期状態を表示する。手動のバックアップ・復元操作は置かない。
- 設定: 学習データ作成ボタン表示、AI利用状況、規約、問い合わせ、データ削除を並べる。
- 学習協力ON時のホーム導線は、通常の手牌訂正とは区別して「学習用の牌を1枚撮影」と表記する。
- 認識結果の導線は「訂正内容を学習データとして送信」と表記し、送信時だけログインを求める。

### 3.7 Web管理画面

**答える質問:** 管理者がデータ品質とモデル公開状態を混同せずに運用できるか。

- 左ナビ: 概要、学習データ、評価、再学習、モデル公開、監査ログ。
- 概要: 収集件数、訂正率、評価精度、現在の公開モデル、直近処理をカード表示する。
- 学習データ: 画像、正解、元予測、confidence、モデル情報、前処理version、採否を一覧・詳細で確認する。
- モデル公開: bundled、候補、公開中を区別し、評価結果を確認してから明示的に公開する。ロールバック先を常に表示する。
- Firebaseのadmin claimがない利用者にはWeb管理機能を表示せず、APIでも拒否する。

## 4. draw.ioページ構成

| ページ名 | そのページが答える質問 |
|---|---|
| `01_モバイル_ホーム` | 目的選択、ログイン状態、補助導線をどう配置するか |
| `02_モバイル_カメラ` | 枚数を1タップで指定しながら自動スキャンする配置は何か |
| `03_モバイル_認識確認と結果` | 画像・牌訂正と目的別結果をどう一画面に収めるか |
| `04_モバイル_対局ホーム` | 局情報、和了者席、補助操作をどう配置するか |
| `05_モバイル_認識中の条件入力` | 認識と並行する条件入力をどう短く進めるか |
| `06_モバイル_履歴と設定` | 履歴同期、設定、学習協力をどう区別するか |
| `07_Web_管理画面` | データ品質、評価、再学習、公開をどう管理するか |

## 5. 図に含めないもの

- ブランドカラー、最終フォント、アイコン素材の指定
- APIの詳細なリクエスト・レスポンス
- 管理者以外へ公開しないモデル情報の一般画面表示
- 卓全体の点棒管理、供託入力、元画像のクラウド同期
