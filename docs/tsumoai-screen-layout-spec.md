# TsumoAI 画面レイアウト図仕様

- 更新日: 2026-09-21
- 対象: モバイル縦画面、Web管理画面
- 状態: 合意済み要件に基づく目標レイアウト。実装済みを示す資料ではない
- 編集可能な図: [TsumoAI 画面レイアウト（draw.io）](./tsumoai-screen-layout.drawio)

## 1. 目的と読者

本書は、実装者とレビュー担当者が「各画面で何がどこに表示され、どの操作を何タップで行うか」を確認するための、画面レイアウト図の意味上の正本である。画面間の遷移は [モバイルナビゲーション仕様](./tsumoai-mobile-navigation-spec.md) と [モバイルナビゲーション図](./tsumoai-mobile-navigation.drawio) を参照する。

図は情報階層と操作位置を定義する。色、フォント、最終的な余白は実装と実機確認で調整する。

## 2. 共通ルール

- 一般利用者向けモバイル画面は縦持ちで完結する。
- 主要操作は片手で押しやすい画面中央から下部へ置き、48dp以上のタップ領域を確保する。
- 1タップで選べる項目をドロップダウンへ隠さない。選択直後に次へ進める設問には確定ボタンを置かない。
- 撮影、認識、条件入力、訂正の途中には広告を置かない。
- 枚数指定は「自動・13・14・15・16・17・18」を常時見せる。初期選択は点数計算・「何を切る」で14枚、待ち確認・鳴き判断で13枚とする。横幅不足時はチップ列だけを横スクロールし、展開操作は加えない。
- 検出枠、牌、枚数、和了牌の訂正は結果画面へ集約する。
- 一般画面にモデルversion、source、前処理versionを表示しない。
- 図中の画面はすべて目標設計であり、現行実装との差分はLinearで管理する。

## 3. 画面別レイアウト

### 3.1 一般ホーム

**答える質問:** 利用者は目的を迷わず選び、アカウント状態も確認できるか。

- 上部: サービス名と右上のログイン／アカウント、設定アイコン。未ログイン時は設定の左へ「ログイン」、ログイン中は同じ位置へアカウントアイコンだけを表示し、タップするとメールアドレスとログアウトを表示する。使い方は設定内へ置く。サービス名直下の説明文や4機能をまとめる見出しは置かず、目的カードを直下へ配置する。各操作領域は48dp以上とする。
- 主領域: 点数計算、待ち確認、何切る、鳴き判断を直接選べる4枚のカードを表示する。4機能をまとめる「牌を撮影して確認」等の見出しは置かない。AI相談を押してから用途を選ぶ中間画面は設けない。
- 次領域: `実際の対局進行に合わせて点数計算を行う` を横幅いっぱいの主要ボタンとして表示し、`点数計算できる人がいない場合に1半荘分の点数計算をサポート` と説明する。対局状態が残っている場合は同じ位置・寸法のカードを `対局を再開` と現在局の表示へ切り替え、再開専用の行を追加しない。単発の点数計算との違いと利用場面をボタンだけで理解できるようにする。利用頻度の低い履歴はホームへ置かず、設定から開く。
- 下部: 開発者設定ON時だけ「学習用の牌を1枚撮影」を表示する。設定、使い方、規約、ログイン状態を重複表示しない。
- 無料利用時の広告は最下部に限定する。

### 3.2 共通カメラ

**答える質問:** 縦持ちのまま、枚数を必要なら1タップで指定し、自動スキャンの状態を理解できるか。

- 上部: 戻る、選択済み目的、スキャン状態、ホーム。その直下を横長のカメラプレビューとし、プレビュー全体を撮影・保存・認識範囲にする。範囲外のカメラ映像は表示も保存もせず、別の内側ガイドは重ねない。検出枠と安定度だけをプレビューへ重ねる。
- カメラ下: 「自動・13・14・15・16・17・18」の直接選択チップ。点数計算・「何を切る」では14、待ち確認・鳴き判断では13を初期選択する。
- 画角選択は表示せず、利用可能な背面カメラをアプリが自動選択する。画面に表示した横長プレビューと、保存画像、位置検出入力、牌識別入力、結果画像の範囲・向き・解像度変換を一致させる。
- 下部: 自動確定までの案内。手動撮影は自動確定できない場合の復旧操作として置く。
- 枚数変更時は同じカメラ入力で検出を継続し、別画面へ遷移しない。

### 3.3 認識確認・目的別結果

**答える質問:** 認識の誤りを直しながら、選択済み目的の結果を確認できるか。

- 上部: 戻る、選択済み目的、検出枚数、ホーム。枚数チップを直接表示し、変更時は同じ画像から再検出する。
- 画像領域: 元画像と検出枠。「範囲を切り抜く」で実装済みの手動トリミングへ進む。
- 牌領域: 認識牌を順番どおり画面幅内で折り返し、最大18枚まで全枚を同時表示する。横スクロールは使わない。牌タップで種類訂正する。枠の追加・削除は設けず、枠が不適切な場合は想定枚数変更による再検出、手動トリミング、または上部の「戻る」でカメラへ戻って撮り直す。別の撮り直しボタンは置かない。
- 牌訂正ダイアログは通常34種と赤五萬・赤五筒・赤五索の計37種を牌画像で一画面に表示する。横スクロール、種類見出し、確定ボタンは置かず、牌を1回タップした時点で置き換えて閉じる。9枚並びを維持しつつ左右余白と牌間隔を抑え、牌画像とタップ領域を最大化する。
- 結果領域: 点数では立直・表ドラ・裏ドラの現在値と変更操作、ツモ・ロン両方の役・翻・符・支払いを表示する。条件変更は即時再計算する。待ちでは待ち牌、何切る・鳴き判断では決定的計算を根拠とする説明とAIチャットを表示する。
- 下部: 条件訂正、同じ認識牌を使って別目的へ移る操作。adminかつ開発者設定ON時だけ訂正データ送信を表示する。
- 待ち確認結果はテンパイ時に全待ち牌を表示し、残り枚数は手牌内の同牌だけを除いた理論上の最大枚数として明記する。捨て牌・副露・他家の手牌は反映しない。テンパイでない場合も13枚のまま向聴数、向聴数を減らす有効牌、各牌の残り枚数を表示する。14枚を前提とする「何切る」へ認識牌をそのまま渡さない。
- 何切る結果は候補を上位3枚まで表示し、各候補へ順位、切る牌、向聴数、受け入れ枚数、短い根拠を添える。初期の判断基準は「牌効率重視」とし、他家の立直や点数状況は考慮していないことを明記する。
- 何切るの判断基準は `牌効率重視 / 打点優先 / 即和了優先 / 守備考慮` から変更できる。守備考慮は他家の立直、捨て牌、巡目など追加情報が必要なため、情報が不足した状態では断定せず、AIチャットで状況を補って判断する。場況・点数状況など画像から分からない条件は任意のAIチャットで追加し、認識牌と上位3候補の計算結果を会話へ自動添付する。AIが利用できない場合も基本計算結果は表示する。会話は利用履歴へ保存する。
- AIチャットは結果画面のボタンから、下からほぼ全画面までせり上がるモーダルで開く。状況テンプレートを複数選び、質問の型を選ぶと質問文を自動生成し、自由編集して送信できる。閉じる・下スワイプで計算結果へ戻り、キーボード表示中は全画面まで拡張する。
- 初期の状況テンプレートには `親リーチ / オーラス / トップ目 / ラス目 / 守備優先 / ドラを残す / 着順UP` を用意し、複数選択できる。`着順UP` は点数状況を踏まえて打点・速度を優先したい意図としてAIへ渡す。
- admin専用のモバイル開発者設定に `AIチャットテンプレート管理` を表示し、状況／質問の型を追加・編集・並べ替え・表示停止できるようにする。version付きのサーバー設定として公開し、アプリ更新なしで反映する。モバイルは端末キャッシュを持ち、取得失敗時は前回のテンプレートを使う。
- 鳴き判断結果は実際に牌が切られる前の確認を前提とし、捨てた牌や相手を入力させない。現在の手牌から鳴ける可能性のある牌を省略せず、牌アイコンと鳴き方を `推奨 / 条件付き / 見送り` の3枠へ分類して表示する。チーは上家から出た場合だけ可能と注記する。
- 鳴き候補の牌をタップすると、候補一覧の中央に詳細ポップアップモーダルを開く。背景タップまたは「閉じる」で一覧へ戻り、下スワイプ操作には依存しない。内容が長い場合はモーダル内だけを縦スクロールする。詳細には可能なチー／ポン／カンの形、鳴いた後の向聴数・受け入れ・狙える役、推奨理由を表示する。「条件付き」には鳴く条件、「見送り」には見送る理由と、判断が変わる条件を明記する。追加の場況判断は共通AIチャットで質問する。
- AI相談の無料回数を使い切った場合は会話を閲覧可能なまま入力欄だけを停止し、次回利用可能日とAIを使わない計算結果を引き続き利用できることを表示する。課金方式が決まるまでは購入導線を置かない。AI回答の取得失敗時は質問文を保持してチャット内に再試行を表示し、計算結果画面全体をエラーにしない。
- 点数計算でツモ・ロンの片方だけ役なし等で成立しない場合、成立する側は通常どおり役・翻・符・支払いを表示し、成立しない側は同じ位置へ理由を表示する。画面全体をエラーにせず、条件変更時に両方を即再計算する。

### 3.4 対局ホーム

**答える質問:** 現在局を確認し、和了者の物理席を1タップで選べるか。

- 上部: 「和了者を選択」を最初に表示し、その直下へ固定座席図を置く。専用の和了ボタンは設けず、席ボタン自体を押して和了処理を開始する。
- 座席ボタンは `東 / 南 / 西 / 北` と表示する。物理的な起家の席へ「起家」バッジ、現在の親の席へ「親」バッジを重ね、局進行に応じて親バッジを移動する。
- 座席図の左上、対面席ボタンの左に `東1局 / 0本場` のような局情報を表示する。右上、対面席ボタンの右に表ドラの登録・変更を置く。表ドラは未登録でも進め、次局でクリアする。
- 座席図の左下に「1局戻す」、右下に「流局」を置く。
- 座席図の直下に、現在の場・局・親・本場・登録済みの表ドラを引き継ぐ点数計算、待ち確認、何切る、鳴き判断の4ボタンを置く。確認の完了だけでは局を進めない。
- 4機能の下に「対局終了」を横幅いっぱいで置く。南4局後も西1局へ進め、終了したい時にこのボタンを押す。

### 3.4.1 流局ダイアログ

**答える質問:** 対局ホームを離れず、親継続または親交代を一度の判断で指定できるか。

- 対局ホームの「流局」を押すと、同じ画面の中央に確認ダイアログを重ねる。独立した流局画面へ遷移しない。
- ダイアログには「親は継続しますか？」と、親継続・親交代の2つの選択肢を表示する。
- 親継続を選ぶと同じ局のまま本場を1増やし、親交代を選ぶと次局へ進めて本場を0へ戻す。選択時に局状態を更新し、ダイアログを閉じる。
- `×` またはダイアログ外の背景タップは状態を変えずに閉じる。キャンセルボタンは置かない。誤って選択した場合は対局ホームの「1局戻す」で復元する。
- 点棒、供託、聴牌人数は入力対象にしない。

### 3.5 認識中の条件入力

**答える質問:** 認識待ち時間を使い、最低限の条件を少ない操作で入力できるか。

- 上部に「撮り直す」、認識進捗、「ホーム」を常時表示する。ホームへ戻る場合も進行中の対局状態は保持する。
- 立直は大きな縦並びボタンで選ぶ。「はい」を上、「いいえ」を下に置き、1タップで直ちに次へ進む。
- 表ドラ表示牌は全34種の牌一覧からタップで直接追加・解除し、追加確認ボタンは置かない。0枚のまま「次へ」を押せる。対局ホームで表ドラ登録済みの場合はこの入力ステップを自動スキップして登録値を引き継ぐ。登録済みの場合も結果画面で追加・修正できる。
- 立直「はい」の場合は必ず裏ドラ表示牌の入力を表示する。対局ホームで表ドラ登録済みでも裏ドラ入力は省略しない。裏ドラ選択画面の上部には現在の表ドラ選択内容を読み取り表示し、裏ドラとの混同を防ぐ。表ドラは「一つ前」または結果画面から修正できる。立直「いいえ」の場合だけ裏ドラ入力を飛ばして結果へ進む。表ドラと同じ1タップ選択とし、0枚でも結果へ進める。
- STEP 2以降は「一つ前」を表示する。表ドラ入力中は立直選択へ、裏ドラ入力中は表ドラ入力へ戻り、入力済みの内容は保持する。STEP 1では同じ位置を「撮り直す」とする。
- ツモ／ロンは入力させず、結果画面に両方を表示する。
- 認識が先に終わっても入力中の画面を奪わず、条件入力完了後に結果へ進む。
- 条件入力が先に終わった場合は、撮影画像、位置検出・牌識別・計算の処理段階、入力済み条件を表示して待機する。追加の確定ボタンは置かず、認識完了時に結果へ自動遷移する。

### 3.6 履歴・設定・学習協力

**答える質問:** 任意ログイン、履歴同期、学習協力の設定を誤解なく扱えるか。

- 履歴: 画面下部に固定した `すべて / 点数 / 待ち / 何切る / 鳴き` のカテゴリタブ、結果一覧、ログイン時のアカウント同期状態を表示する。`さらに表示` ボタンは置かず、一覧を縦スクロールすると古い履歴を順次読み込む。項目を押すと当時の結果詳細を開く。未ログイン時は端末内だけに保存し、ログイン後はアカウントへ自動同期する。手動のバックアップ・復元操作は置かない。履歴削除は設定へ集約する。
- ログイン中にオフラインになった場合も新しい履歴を端末へ即保存・表示し、同期待ち件数と対象履歴を表示する。通信復帰時に自動反映し、手動同期ボタンは置かない。
- 履歴詳細は専用画面で開く。点数は役・翻・符・支払い、待ちは待ち牌と残り枚数、何切る・鳴き判断は認識した牌と判断条件を表示する。AI会話は詳細画面へ直接展開せず、「AIとの会話を見る・続ける」から他機能と共通のAIチャットを下から表示する。過去の会話全文を縦スクロールで確認でき、入力欄から同じ会話を継続できる。追加した会話は同じ履歴へ追記し、ログイン中はアカウントへ同期する。履歴一覧へ戻った時は元のカテゴリとスクロール位置を保持する。
- 設定: 利用履歴、AI利用状況、使い方・ヘルプ、利用規約、プライバシーポリシー、問い合わせ、利用履歴の削除を並べる。利用履歴を押すと履歴一覧へ進む。削除対象は未ログインならこの端末の履歴、ログイン中ならアカウントに紐づく同期済み履歴と明記する。「クラウドデータ」という曖昧な名称は使わない。開発者設定はadminだけに表示する。ヘルプへ撮影のコツを常設せず、撮影操作はカメラ画面自体で理解できるようにする。
- 問い合わせの返信先は任意入力させず、Googleログインで確認済みのメールアドレスへ固定する。未ログイン時は問い合わせ送信時だけログインを求める。画像と診断情報は利用者が明示的に選んだ場合だけ添付し、自動添付しない。
- 利用履歴の削除確認では、結果履歴と保存済みAI会話が削除対象で、アカウントと送信済み学習データは対象外であることを明示する。ログイン中は同じアカウントに紐づく全端末の履歴を削除する。
- `学習データ作成ボタンを表示` は一般設定ではなくadmin専用の開発者設定に置く。ON時だけホームへ、通常の手牌訂正とは区別した「学習用の牌を1枚撮影」を表示する。
- 開発者設定で学習データ作成表示がONの場合だけ、認識結果に「訂正内容を学習データとして送信」を表示し、adminログイン中だけ表示・送信を許可する。
- 訂正内容の送信ボタンには訂正枚数と、画像・正解ラベル・元予測・認識時のモデル情報を送ることを短く示す。確認ダイアログは追加せず、1タップで送信して同じ場所を「送信済み」へ変える。送信しても計算結果と利用履歴は変更しない。
- 開発者設定の切替は導線の表示だけを変更し、利用モデルや公開versionを変更しない。OFFに戻しても送信済み学習データは削除しない。
- 開発者設定に「Web管理ダッシュボードを開く」を表示する。遷移先のWebでもログインとFirebase `admin: true` claimを再検証し、権限がない場合は管理画面を表示せずAPIも拒否する。

### 3.7 Web管理画面

**答える質問:** 管理者がデータ品質とモデル公開状態を混同せずに運用できるか。

- 左ナビ: 概要、学習データ、評価、再学習、モデル公開、監査ログ。
- 概要: 収集件数、訂正率、評価精度、現在の公開モデル、直近処理をカード表示する。
- 学習データ: 保存済みデータは再学習時に原則すべて使用し、1件ずつ採用・保留へ振り分けない。一覧上部で正解牌、元予測、使用モデル、データ出所を絞り込む。一覧を画面幅いっぱいに表示し、先頭列の実画像サムネイルとID、正解、元予測、confidence、モデル情報、前処理versionを各行だけで確認できるようにする。元予測には現在の正解ラベルとの一致を `○ / ×` で併記し、訂正有無の独立列は置かない。常設の詳細パネルは置かない。正解列は各行で直接変更できる牌選択欄とし、変更時に保存する。画像自体が学習に使えない場合は行末の操作メニューから削除し、削除前には確認ダイアログを表示する。
- 評価: 公開中モデルと候補モデルを同じ固定評価セットで比較する。牌単位正解率、手牌完全一致率、認識成功率、失敗ケース数、評価件数を別々に表示し、単一の「精度」へまとめない。学習時のランダム分割によるvalidation accuracyは参考値として固定評価セットの結果と明確に分ける。候補と公開中モデルの差分、主な誤分類、失敗理由、評価履歴を表示し、評価画面から直接公開せずモデル公開画面へ進む。
- 再学習: 実行前に学習データ件数、牌別の不足・偏り、epochs、対象ブランチ、リージョン、想定時間、概算費用を表示する。開始ボタンは確認ダイアログを経てCloud Buildを1件だけ起動し、実行中は重複起動できない。状態は待機中、実行中、成功、失敗と経過時間、ログへの導線で表示し、過去の実行履歴も同じ画面で確認できる。成功時は候補モデルを作るだけで自動公開せず、固定評価セットでの評価へ進む。
- モデル公開: アプリ同梱、公開中のダウンロード版、候補を区別し、候補の固定評価結果、labels、schema、前処理互換性、hashを確認してから確認ダイアログ経由で明示的に公開する。公開はサーバーのactive versionを切り替え、モバイルは次回起動時に取得する。端末は現在版と直前版、アプリ同梱版を保持し、検証失敗時は現在版を維持する。過去の承認済みversionと評価値をロールバック先として常に表示し、切り戻しも確認ダイアログ経由で行う。
- 監査ログ: 学習データのラベル変更・削除、再学習開始、評価実行、モデル公開・ロールバック、AIチャットテンプレート変更をサーバー側で記録する。日時、実行者、操作、対象、成否、操作IDを一覧で表示し、期間、操作、成否、実行者で絞り込む。常設の詳細パネルは設けず、行内の概要と必要時の操作メニューで確認する。画像内容、ID token、APIキーなどの秘密情報は記録・表示しない。現行は統一監査ログが未実装のため、この画面の実装時に記録基盤も追加する。
- Firebaseのadmin claimがない利用者にはWeb管理機能を表示せず、APIでも拒否する。

## 6. 共通ビジュアル仕様

- 基調色は `#176B52`、濃色は `#0D4F3B`、背景は `#F6F8F5`、通常面は `#FFFFFF`、本文は `#1A3027`、補助文字は `#718078` とする。
- 情報は `#34699A`、注意は `#D29A22`、削除は `#C74646`、開発者機能は `#7652A5` を使う。色だけで状態を伝えず、文言・アイコン・枠も併用する。
- 主要ボタンは高さ52dp、その他のタップ領域も原則48dp以上とする。画面左右余白16dp、カード間12dp、カード内12〜16dp、通常カード角丸16dp、モーダル角丸24dpを基準とする。
- 共通ヘッダーは左に戻る、中央に画面名と必要最小限の状態、右にホームを固定する。見た目のアイコンが24dp前後でもタップ領域は48dpを確保する。
