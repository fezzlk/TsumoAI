# ADR 0001: バックエンド実装言語とPythonランタイム

- 状態: Accepted
- 決定日: 2026-09-04

## Context

TsumoAIのバックエンドは、麻雀の牌姿解析・点数計算に加えて、画像前処理、牌分類、
認識精度評価、モデル学習支援を扱う。モバイルアプリはFlutter/Dartで実装され、
端末内のTFLite推論はモバイル側でも実行する。

これまでPythonとFastAPIを利用していたが、言語選定理由とサポート対象バージョンが
明文化されていなかった。また、DockerとCIはPython 3.11、既存の開発用venvは
EOL済みのPython 3.9という不一致があった。

## Decision

バックエンド、画像処理、学習・評価ツールの主要言語としてPythonを継続する。
サポートするPythonランタイムは3.11系に統一する。

採用理由:

- OpenCV、Pillow、TensorFlow Liteなど既存の画像認識資産を直接利用できる。
- 推論、学習、評価、APIを同じ言語で扱い、精度改善を反復しやすい。
- FastAPIとPydanticによりAPI境界と入力スキーマを明示できる。
- 現在の牌姿解析性能は要件を満たし、言語変更で解決すべき性能問題が確認されていない。
- 麻雀ドメインを画像認識やHTTPから分離することで、Pythonを維持したままテスト性を確保できる。

Python 3.11を選ぶ理由:

- Docker、Cloud Build、GitHub Actionsですでに利用している。
- `tflite-runtime==2.14.0`の公式Linux wheelが提供されている。
- Python 3.11は2027年10月までセキュリティサポート対象である。

## Consequences

- ローカル開発、CI、コンテナでPython 3.11を使用する。
- `.python-version`をランタイム指定の正本とし、DockerfileとCIも同じminor版に合わせる。
- Python 3.9以下での動作は保証しない。
- 画像認識、牌姿解釈、麻雀ドメインのモジュール境界は維持し、Python固有型を外部API契約へ漏らさない。
- FlutterとPythonに同じ麻雀ロジックを重複実装しない。端末内でドメイン計算が必須になった場合は、
  共有可能な実装への切り出しを別ADRで判断する。

## Reconsideration triggers

次のいずれかが発生した場合、言語またはランタイムを再検討する。

- Python 3.11のEOLが12か月以内に近づいた。
- `tflite-runtime`の保守状況がセキュリティまたは対応環境の制約になる。
- サーバー側のCPU使用量、コールドスタート、処理時間が計測済みSLOを満たさない。
- 完全オフライン動作のため、Flutterと共有できる麻雀ドメイン実装が必要になる。
- 対応する画像認識ランタイムがPython以外を主要経路とする。

2027年前半を目安に、TensorFlow Liteランタイムの後継、依存パッケージのwheel提供状況、
Python 3.13以降への移行を評価する。

## Alternatives considered

### TypeScript / Node.js

APIと型共有には利点があるが、現在の画像処理・学習資産を移行または別サービス化する必要があり、
現時点の便益を上回らない。

### Dart

Flutterとの統一には利点があるが、サーバー側の画像処理、学習、評価エコシステムで既存Python資産を
置き換える負担が大きい。

### Rust

性能と共有ライブラリ化には利点があるが、現状の性能は要件内であり、FFI・ビルド・ML連携の複雑性が
先行する。将来、端末とサーバーで同じドメイン計算を共有する必要が生じた場合の候補とする。
